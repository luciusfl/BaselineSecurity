WINDOWS 11 SECURITY CONFIGURATION BASELINE

PREREQUISITES:

  • Operating System: Windows 11 or later
  • PowerShell: Version 5.1 (powershell.exe). Comes with Windows 11.
  • Environment: Standalone personal computer (unmanaged, non-domain joined, no corporate Group Policy)

Stand-alone check: Before it changes anything, Remediations.ps1 checks whether an organization manages the PC. It stops without making changes if any of the following is found:

  • The PC is joined to an Active Directory domain, which is required for domain Group Policy (Win32_ComputerSystem PartOfDomain; Microsoft documentation).
  • The PC is joined to Microsoft Entra ID (cloud or hybrid) or to an on-premises device registration service, or a work or school account is registered under Settings > Accounts > Access work or school (dsregcmd /status shows AzureAdJoined, EnterpriseJoined, DomainJoined or WorkplaceJoined as YES; Microsoft documentation).
  • The PC is enrolled in MDM such as Microsoft Intune: an active enrollment with an MDM server, or an OMA-DM server account in the registry.
  • The Microsoft Configuration Manager client (service CcmExec) or the Microsoft Intune Management Extension is installed.

On such a PC, the organization's policies should set these settings. Audit.ps1 still runs because it only reads settings, and Rollback.cmd can still undo changes made before the PC was joined or enrolled. Third-party remote management tools that do not use these Windows mechanisms are not detected.

Number of security checks: more than 300 documented security settings. The exact number Audit.ps1 runs depends on the computer: each of the 40 system services in the CIS Chapter 5 row is checked separately, and checks for browsers that are not installed or features not available on the installed Windows version are skipped. Settings that Remediations.ps1 configures but Audit.ps1 does not check are marked "not audited" and are not counted.

Under each failed check, Audit.cmd shows what the setting does and why it matters for security. All of this text is in one file, AuditCheckDetails.json, next to Audit.ps1. For CIS recommendations it is the Description and Rationale of the CIS benchmark, copied into that file from the benchmark. For the other checks it is a summary with links to the sources. By default the scheduled hourly audit runs as LocalService, not elevated: the checks that need administrator rights are then not run (SecurityAudit.log lists them as [ELEVATION REQUIRED]) and never count as failures. Install it with Install.cmd -RunAuditElevated to run every check as SYSTEM. The scheduled audit shows the details too, so they are also in %ProgramData%\SecurityAudit\SecurityAudit.log and, after the list of failures, in SecurityAuditErrors.log (the file the "Open log" button of the notification opens).

Checks marked audit-only are not fixed by Remediations.ps1. When one fails, the audit message ends with "Not fixed by Remediations.ps1:" followed by the reason and what to do instead. Where a check accepts more than one value (for example 1 or 2), Remediations.ps1 leaves an existing accepted value unchanged, so a stricter setting is not weakened.

Enabled (True) PowerShell: Confirm-SecureBootUEFI. Audit-only: a firmware (UEFI) setting that Windows cannot change; turn it on in the firmware setup.

Kernel Security Memory Integrity (HVCI) Uses virtualization-based security to prevent untrusted code from running in the Windows kernel, reducing kernel compromise risk. Microsoft documentation. Enabled (Running) Registry: HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity (Enabled = 1); PowerShell: Get-CimInstance -Namespace root\Microsoft\Windows\DeviceGuard -ClassName Win32_DeviceGuard (SecurityServicesRunning contains 2). Audit-only: Remediations.ps1 does not turn Memory Integrity on, because an incompatible kernel driver is blocked and, if Windows needs that driver to start, Windows may not boot. Privacy & Data Minimization Lock Screen Widgets Disabled The lock screen widgets ("Weather and more") show content fetched from the internet on the lock screen before anyone has signed in. Turning them off for all users keeps the lock screen minimal. Not a CIS or Microsoft baseline recommendation. Microsoft documentation (Policy CSP NewsAndInterests, "Disable Widgets On Lock Screen"). Disabled (DisableWidgetsOnLockScreen = DWORD 0) Registry: HKLM:\SOFTWARE\Policies\Microsoft\Dsh\DisableWidgetsOnLockScreen. Audit: Audit.ps1; remediation: Remediations.ps1 (with rollback). The value 0 hides the widgets and 1 shows them (tested on Windows 11 build 10.0.26300; a web guide on majorgeeks.com also says 0). If Windows ever changes the meaning, the check and the remediation must change together. Without the policy, each user can turn the widgets on in Settings > Personalization > Lock screen.
